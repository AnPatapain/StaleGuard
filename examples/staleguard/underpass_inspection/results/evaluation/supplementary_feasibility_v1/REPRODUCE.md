# Reviewer reproduction: evidence for Claims 1–3

Run from `examples/staleguard` in the supplied SCG/PyBullet environment (`conda activate scg`).
There are two distinct operations: regenerate analysis from archived physical flights, or rerun the supplementary physical experiment. Neither requires rerunning the nine-policy benchmark.

## Data locations

- `underpass_inspection/results/evaluation/supplementary_feasibility_v1/`: supplementary physical journal, configuration/checkpoint and exported results. Its `predictions.jsonl` is intentionally empty.
- `underpass_inspection/results/evaluation/baseline_benchmark_v2/`: original 400-scenario, 46,800-flight benchmark. Its `predictions.jsonl` contains the saved approval-time forecasts and measured runtimes used here.
- `geofence_turn/results/evaluation/baseline_benchmark/` and `inspection_descent/results/evaluation/baseline_benchmark/`: archived other-mission journals and configurations.

For analysis, retain `run.json`, `progress.json`, `executions.jsonl`, `predictions.jsonl`, and `metrics.json` from the original Underpass benchmark; the supplementary analysis copy needs the five files listed in command A. The other two missions need their original `run.json` and `executions.jsonl`. CSV summaries alone are insufficient. Physical reproduction also needs the original Underpass benchmark's `approval_snapshots.npz` and the frozen physical software/environment.

## A. Regenerate every table and figure from archived data: no simulation

Use a separate working copy so the submitted artifacts are unchanged. This also avoids relying on absolute paths from the author's workspace; `--source` explicitly locates the unchanged original benchmark and verifies its recorded hashes.

```bash
mkdir -p /tmp/staleguard-supplementary-reviewer
cp underpass_inspection/results/evaluation/supplementary_feasibility_v1/{run.json,progress.json,executions.jsonl,predictions.jsonl,validation.json} /tmp/staleguard-supplementary-reviewer/
python underpass_inspection/support/supplementary_analysis.py \
  --source underpass_inspection/results/evaluation/baseline_benchmark_v2 \
  --out /tmp/staleguard-supplementary-reviewer
```

Results appear in `/tmp/staleguard-supplementary-reviewer/`: both PNG/PDF figures, CSV exports, `metrics.json`, `REPORT.md`, and `TECHNICAL_APPENDIX.md`. Repeating the analysis command does not fly the UAV or rerun the predictor. Numerical analysis reproduces the archived study; the historical all-artifact audit coverage differs because the reviewer copy intentionally omits the author's broad historical-file inventory. The original journal/configuration and source hashes are still checked.

Runtime numbers reproduce the previously measured warmed forecasts. Retiming on another computer would answer a different hardware-dependent question and need not yield the same milliseconds.

## B. Independently rerun the supplementary physical experiment

Choose a fresh output directory. This runs **11,200** new physical flights and reuses the same **4,000** No Recovery records; it does not rerun 46,800 policy flights. All recovery starts are independently simulated, with no predicted feasibility labels used as truth.

```bash
python underpass_inspection/support/feasibility_sweep.py \
  --source underpass_inspection/results/evaluation/baseline_benchmark_v2 \
  --out /tmp/staleguard-supplementary-physical-reviewer \
  --workers 4
```

Resume only if interrupted (not needed after successful completion):

```bash
python underpass_inspection/support/feasibility_sweep.py \
  --source underpass_inspection/results/evaluation/baseline_benchmark_v2 \
  --out /tmp/staleguard-supplementary-physical-reviewer \
  --workers 4 --resume
```

Then generate the same tables/figures from those newly executed physical flights:

```bash
python underpass_inspection/support/supplementary_analysis.py \
  --source underpass_inspection/results/evaluation/baseline_benchmark_v2 \
  --out /tmp/staleguard-supplementary-physical-reviewer
```

The completed journal has 15,200 unique physical records. A second completed-run resume adds zero flights. Frozen approval/PID inputs, full horizon, 1,000 Hz safety monitoring and immediate-recovery reference hashes are checked by the driver.

## C. Focused tests: no physical flights

```bash
python -m unittest underpass_inspection.support.test_supplementary -v
```

These test candidate alignment, first-loss versus last-safe conventions, censoring/non-monotonicity, confusion denominators and rounded readiness/equality handling.

## D. Regenerate the original nine-policy outcome table and reports: no simulation

This supplies the full main policy table (all nine policies), not only the supplementary paired-comparison tables. Work on a copy so historical derived files remain unchanged.

```bash
mkdir -p /tmp/staleguard-benchmark-reviewer
cp underpass_inspection/results/evaluation/baseline_benchmark_v2/{run.json,progress.json,executions.jsonl,predictions.jsonl} /tmp/staleguard-benchmark-reviewer/
python underpass_inspection/baseline_benchmark/run.py \
  --out /tmp/staleguard-benchmark-reviewer --metrics-only
```

This regenerates the nine-policy `REPORT.md`, `TECHNICAL_APPENDIX.md`, `metrics.json`, `per_scenario.csv` and `per_delay.csv`, with the existing scenario-level confidence intervals. It requires neither a calibration rerun nor new flights. The supplementary paired tables and two-panel policy plot remain command A outputs, derived from the same archived executions.
